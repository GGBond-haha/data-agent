# 掌柜问数 Data Agent
## 项目简介
本项目为 NL2SQL 自然语言查询智能体的实践复现项目，基于 LangGraph 编排多节点 Agent 工作流，结合向量检索、全文检索双引擎的 RAG 增强方案，实现端到端的中文自然语言转 SQL 查询能力。

用户只需输入口语化业务问题，系统即可自动完成语义解析、元数据召回、SQL 生成校验、数仓查询全流程，无需手动编写 SQL，大幅降低业务人员的数据分析门槛。

## 核心功能
- 自然语言转 SQL：支持中文口语化提问，自动生成符合数仓语法的可执行 SQL
- 多路召回增强：向量语义召回 + 全文精确检索双引擎，提升表字段与业务指标的匹配准确率
- SQL 自动纠错：内置语法校验节点，生成失败时自动触发 LLM 最小化修复，提升查询成功率
- 流式进度反馈：基于 SSE 协议实时推送查询进度与结果，优化前端交互体验
- 元数据可扩展：结构化维护表、字段、业务指标元数据，支持知识库增量更新与重建

## 技术栈
| 模块分类 | 技术选型 | 核心作用 |
| :--- | :--- | :--- |
| 服务框架 | FastAPI | 异步 HTTP 服务，提供查询接口与流式输出能力 |
| Agent 编排 | LangGraph | 状态图式编排多节点工作流，支持并行执行与条件路由 |
| LLM 调用 | LangChain + DeepSeek 大模型 | 统一 Prompt 管理与大模型调用，负责语义理解与 SQL 生成 |
| 向量检索 | Qdrant + BGE 中文 Embedding 模型 | 实现字段、指标的语义相似度召回 |
| 全文检索 | Elasticsearch + IK 分词器 | 实现字段枚举值的中文精确匹配 |
| 数据存储 | MySQL | 分别存储结构化元数据与业务数仓数据 |
| 工程组件 | SQLAlchemy、jieba、OmegaConf | 异步 ORM、中文分词、统一配置管理 |
| 环境管理 | Miniconda | 隔离 Python 项目依赖，统一本地运行环境 |

## 核心业务流程
系统基于 LangGraph 设计 6 大阶段、12 个节点的 Agent 工作流，单次查询执行链路如下：
1. **语义解析**：使用 jieba 分词提取问题核心关键词，合并原始问题形成初始检索词集合
2. **多路并行召回**：三条支路并发执行，覆盖不同召回场景
    - 字段语义召回：LLM 扩展字段关键词，通过 Qdrant 向量检索匹配相关字段信息
    - 指标语义召回：LLM 扩展指标概念词，向量检索匹配对应业务指标定义
    - 字段取值召回：ES 全文检索匹配字段枚举值，为 SQL 的 WHERE 条件提供准确依据
3. **信息合并**：去重融合三路召回结果，补全表主外键与指标关联字段，构建结构化上下文
4. **LLM 精筛**：大模型二次过滤冗余表、字段与指标，缩减上下文噪声，提升生成精度
5. **上下文增强**：动态注入当前日期、数据库版本信息，优化时间类 SQL 生成与语法兼容性
6. **SQL 生成与执行**：LLM 生成 SQL → EXPLAIN 语法校验 → 校验失败自动纠错 → 异步执行并流式返回结果
